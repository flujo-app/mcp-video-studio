# Acceptance productions

The 30-second delivery gate creates a real 1920x1080,30fps project through public MCP tools. Provided inputs are prepared independently: moving video, an original synthesized voiceover fixture, and a generated chord bed. Project creation, imports, edits, transitions, HTML animation, title and caption authoring, music ducking, final-mix normalization, revision-conflict repair, reopening, render and QC use MCP exclusively. Decoder inspection verifies the delivered artifact; no project JSON files or caller-authored renderer filtergraphs are used for the editing workflow.

Run RUN_PROMO_INTEGRATION=1 npx vitest run tests/promo-production.integration.test.ts after a clean install and build with FFmpeg/ffprobe and Patchright Chromium available. The test requires exactly900 decoded H264 frames,1920x1080,30/1fps,48kHz stereo AAC,faststart and every structured QC check PASS. It verifies that a second server process can add an independent review marker, that stale author edits are rejected, and that targeted repair preserves unrelated clips and the review. A fresh server reopens the committed project before rendering. Inputs and results are cleaned unless PROMO_ACCEPTANCE_KEEP is set; PROMO_ACCEPTANCE_EVIDENCE can receive a small JSON evidence report. These are test-only environment options.

The first local run of the complete production passed all12 QC checks, including six caption safe-area measurements, -16.45LUFS and -4.56dBTP. Render plus full QC took58.1seconds on the remediation workstation. Cross-platform CI reruns the fixture against the actual installed runtimes; a local pass is not a substitute for that gate.

The one-minute editor and agent counterpart share provided moving video, music and still-image fixtures. Every project mutation in the browser counterpart uses visible Studio controls; its MCP connection only launches Studio and reads job status. The agent counterpart uses actual modern 2026-07-28 and legacy 2025-11-25 MCP sessions. Both preserve the earlier edit matrix: linked split, durable undo/redo, an independent editor conflict and targeted repair are checked through their appropriate interfaces.

Both counterparts continue through an editable animated title, caption text/style authoring, measured clipping and safe-area repair, audio processing and final-bus loudness normalization, H.264/AAC export, structured QC and a durable reopen. The browser additionally reviews a detected intentional five-second still-image hold by navigating to its measured range and recording an explicit reason; unrelated QC warnings cannot be waived. Final delivery must contain exactly 1,800 fully decoded 1920x1080 frames at 30/1 fps, stereo 48 kHz AAC, a finite 60-second duration, faststart and all applicable QC checks passing. Video-frame QC is checked explicitly; metadata inspection alone is insufficient.

Run RUN_FFMPEG_INTEGRATION=1 RUN_BROWSER_INTEGRATION=1 npx vitest run tests/core-editing-browser.integration.test.ts tests/agent-editing-production.integration.test.ts after building. The clean packed installation gate repeats both workflows against the installed CLI entry point, with all five other installed browser workflows. Test-only MINUTE_ACCEPTANCE_KEEP retains fixture directories; MINUTE_ACCEPTANCE_EVIDENCE names an existing directory receiving human-minute.json and agent-minute.json. Set TMPDIR/TEMP to a durable evidence directory when retaining outputs.

These are automated functional counterparts. They do not establish an unfamiliar human's usability, subjective media quality or screen-reader judgment; those acceptance gates remain explicit.

These remain separate acceptance gates, with evidence in ACCEPTANCE.md and their integration tests.
